### 4. Runvil and the Runvil Workshop

The instructor described Runvil as a prompting language in which the author decides which part has authority, and the Workshop as an IDE that understands Runvil prompts and can replay recorded runs.

- In Runvil the author decides whether code or the model orchestrates. The model starts with authority to perform inference. Classification can be delegated to a classifier but does not have to be. Lua orchestration and model orchestration can be mixed within one prompt, and the author can offer different tools in different sections, including ad hoc tools invented for the prompt.
- The instructor wants to keep using Cursor but does not control it. Cursor sends the user's prompt to its own server to enrich the context before it goes to Anthropic, and the instructor wants to enrich context his own way and decide what stays or goes when the agent compacts. An interviewer prompt, for example, might keep only the last two stories and compact more often to lower token costs.
- Workshop features described: load a prompt, run it with a keyboard shortcut, set a breakpoint, inspect the store, files, and variables, change something, and run again.
- Runvil can record every tool call, Lua function call, and model interaction. Replaying the recording returns to a breakpoint without redoing inference, so the author of a ten-step pipeline can fix step 7 without rerunning steps 1 through 6, which can take half an hour to two hours.
- The Workshop will be integrated with Runvil. No questions were asked at this point.

### 10. Runvil Design Repository and Gateway Protocols

The instructor pointed participants to a separate repository of his design reports and explained that the gateway must translate between a generic OpenAI-style protocol and each vendor's own API.

- The design repository holds his reports, much of it out of date, and newer material is more reliable. The research directory holds reports he generated by having a prompt research a topic on the web, which is how he learned how agent harnesses work. An example is presenting a prompt as an MCP tool.
- The gateway currently speaks the generic OpenAI-style protocol, where a request contains messages and tools and the reply is the response. Getting the most from Claude, ChatGPT, and other frontier models requires their own APIs, and a document in the repository describes the differences. The gateway needs to implement them.
- Anthropic models return thinking blocks with a cryptographic signature that must be sent back unchanged. Editing, removing, or reordering earlier content breaks the chain, which kicks the caller out of the cache, and the request is rejected with an HTTP error. The instructor's reason for the signature is that tamper-proof thinking makes distillation harder.
- OpenAI returns encrypted, redacted thinking blocks that must also be sent back as received, or the request is rejected. Tool handling differs slightly between vendors as well.
- The gateway goal is to support the generic API plus just enough extensions that other apps using the gateway are unaffected, while Runvil uses minimal extensions that the gateway translates into each proprietary API. This needs some cooperation from the Runvil engine.
- A participant asked whether the internal protocol between the gateway and the engine is worked out. The instructor said it is in the document and is not complicated.
- The instructor said this kind of technical detail is the tacit knowledge to extract, and that reading the Rust code would overwhelm a reader without revealing it.

### 11. How an Agent Harness Works in Runvil

The instructor walked through how a chat message reaches the model and returns, and a participant added that system prompts and context files are also sent.

- The agent packs the chat history and the new input, sends it to the gateway, the gateway sends it to Claude, and the reply returns through the gateway to the Workshop as chat. An extension streams the words as they arrive.
- Runvil keeps a stack of messages that grows with each turn, and the whole stack goes to the model every time. When it grows too large it is compacted, which the instructor called the AI lobotomy.
- In a Runvil prompt the collection is called messages. The chat prompt, in the agents directory, takes input from the user's input box, appends it to messages with a builder, and runs the tool loop described in the lesson document.
- The system prompt and a context file such as Chat MD [?] are part of the messages, as the instructor confirmed after a participant raised them.
- The messages object in Lua is backed by a Rust struct. Data that Lua cannot see can be added to it, for example the tool catalog the gateway needs.
- The instructor wants sessions under an hour, like a 50-minute high school class, and the organizer tracked the time.
